Scope: compare runtime behavior registrations in [`kevinbudz/realm-server`](https://github.com/kevinbudz/realm-server/tree/bb75bc1e438b465986a8ada354b6332f69e0e3a6) at `bb75bc1e438b465986a8ada354b6332f69e0e3a6` against [`ossimc82/fabiano-swagger-of-doom`](https://github.com/ossimc82/fabiano-swagger-of-doom/tree/6fd20aad4a7905b13f25389c68368a942a2b68cb) at `6fd20aad4a7905b13f25389c68368a942a2b68cb` (2015-11-09). ## Method and counts

Target GameData has 2,577 unique object IDs, including 639 with `<Enemy/>`. The target loader enumerates all `IBehaviorDatabase` types and `Init` resolves IDs through `Resources.Id2Object` ([BehaviorDb.cs:74](https://github.com/kevinbudz/realm-server/blob/bb75bc1e438b465986a8ada354b6332f69e0e3a6/Game/Logic/BehaviorDb.cs#L74), [BehaviorDb.cs:88](https://github.com/kevinbudz/realm-server/blob/bb75bc1e438b465986a8ada354b6332f69e0e3a6/Game/Logic/BehaviorDb.cs#L88)); the 40 grouped DB files contain 535 unique registration names, 534 XML-resolvable and 1 unresolved. The unresolved name is `Thessal Dropper` in `OceanTrench.cs:255`; it does not become a runtime registration because the XML lookup returns early. `InitMany` in [Misc.cs:29](https://github.com/kevinbudz/realm-server/blob/bb75bc1e438b465986a8ada354b6332f69e0e3a6/Game/Logic/Database/Misc.cs#L29) expands by object type from Black Cat through Snowman inclusive; the loaded target descriptor interval contains 66 actual IDs. The target XML loader rejects duplicate IDs/types in debug and assigns unique type keys ([Resources.cs:79](https://github.com/kevinbudz/realm-server/blob/bb75bc1e438b465986a8ada354b6332f69e0e3a6/Common/Resources.cs#L79)).

Reference GameData has 3,849 unique object IDs. The reference project compiles 48 behavior DB files; its constructor invokes only nonpublic instance fields whose type is `_` ([BehaviorDb.cs:56](https://github.com/ossimc82/fabiano-swagger-of-doom/blob/6fd20aad4a7905b13f25389c68368a942a2b68cb/wServer/logic/BehaviorDb.cs#L56)). There are 47 executable instance initializer fields: 46 explicit name-based groups (423 IDs) plus `_Pets`, which dynamically registers all 130 entries in `TypeToPet` through [BehaviorDb.Pets.cs:18](https://github.com/ossimc82/fabiano-swagger-of-doom/blob/6fd20aad4a7905b13f25389c68368a942a2b68cb/wServer/logic/db/BehaviorDb.Pets.cs#L18) and the `Class=Pet` parser in [XmlDatas.cs:202](https://github.com/ossimc82/fabiano-swagger-of-doom/blob/6fd20aad4a7905b13f25389c68368a942a2b68cb/db/data/XmlDatas.cs#L202). The 48-file project includes a fully commented Nexus DB; `BehaviorDb.CubeGod.cs` is static legacy and excluded from the project; SkullShrine and IceCave are also not compiled. Of the dynamic pets, 59 exact IDs overlap the target's InitMany pet range, 10 more exist in target XML but lack target registration, and 61 are absent from target XML. The 423 explicit registrations and 130 dynamic pet types map one-to-one to 553 unique reference types, so none overwrite another model. All target XML types are unique.

The enemy-only comparison yields 52 reference enemy definitions whose IDs exist in target XML but lack target behavior registration, plus 49 reference enemy definitions whose IDs are absent from target XML. The supporting non-enemy roster adds 21 target-supported object/pet gaps and 64 reference-only object/pet entries. Together these are 186 unregistered reference IDs (73 target-XML-supported and 113 ref-only). No supported candidate is covered through a target numeric alias. Full machine-readable row set is [coverage.tsv](coverage.tsv), and the expanded raw inventories are in [coverage.json](coverage.json).

The 21 target-supported non-enemy rows comprise 11 explicit object definitions plus 10 dynamic pets; the 64 reference-only non-enemy rows comprise 3 explicit object definitions plus 61 dynamic pets. The target InitMany interval has 7 additional target-side pet IDs without a TypeToPet counterpart in the reference.

The inventory method scans target registrations and embedded XML IDs, reference compiled named registrations, and the reference `TypeToPet` pet loader; it then classifies each active reference ID against target XML and behavior registrations. The TSV and JSON preserve the resulting row-level evidence.

Rows give one candidate per active reference ID, including the dynamic companion-pet loader. “Target XML” source is the exact target object descriptor; `Enemy=yes/no` follows its literal `<Enemy/>` tag. Target absence is determined by scanning all 40 target DB files for `db.Init`, string-array `db.Init`, and expansion of the sole `InitMany` interval. Ref source gives the active DB initializer line. Group means the target embedded XML file.

## Compatibility limits

The reference snapshot is dated 2015-11-09, while the target is a later fork and GameData can contain later content or changed names. “Target XML-supported” means the exact object ID is loadable from this checkout, not proof that it was expected in a 2014 protocol/client build. Conversely, “reference-only” describes absence from the target’s current embedded XML and should not be treated as a migration defect without checking the target’s intended client/build. Names do not establish encounter-map reachability; reachability from specific maps is outside this registration-coverage report’s scope.
