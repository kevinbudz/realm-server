# Enemy behavior definition registration validation

Compared target `kevinbudz/realm-server` at commit `bb75bc1e438b465986a8ada354b6332f69e0e3a6` with reference `ossimc82/fabiano-swagger-of-doom` at commit `6fd20aad4a7905b13f25389c68368a942a2b68cb`. Both repositories were clean when validation began. At final inspection, the reference remained clean; the target had an untracked `docs/` directory from parallel audit-document work, while the tracked server source remained unchanged by this validation. This is a source and project-configuration audit; it does not run either server.

## Loader boundary

The target constructs its behavior database by reflecting over the calling assembly and instantiating every non-interface type assignable to `IBehaviorDatabase` ([target loader](https://github.com/kevinbudz/realm-server/blob/bb75bc1e438b465986a8ada354b6332f69e0e3a6/Game/Logic/BehaviorDb.cs#L71), [database-class loop](https://github.com/kevinbudz/realm-server/blob/bb75bc1e438b465986a8ada354b6332f69e0e3a6/Game/Logic/BehaviorDb.cs#L74)). The target has 40 database classes under `Game/Logic/Database`. Each class registers its IDs through `Init`; the only `InitMany` call is the pet range in `Misc` ([target Misc](https://github.com/kevinbudz/realm-server/blob/bb75bc1e438b465986a8ada354b6332f69e0e3a6/Game/Logic/Database/Misc.cs#L29)). An ID is resolved through `Resources.Id2Object` before a model is stored by object type ([target registration](https://github.com/kevinbudz/realm-server/blob/bb75bc1e438b465986a8ada354b6332f69e0e3a6/Game/Logic/BehaviorDb.cs#L88)). Although resources also populate `IdLower2Object`, this registration path does not use that lowercased map ([target resource maps and loader](https://github.com/kevinbudz/realm-server/blob/bb75bc1e438b465986a8ada354b6332f69e0e3a6/Common/Resources.cs#L15), [target exact-key lookup](https://github.com/kevinbudz/realm-server/blob/bb75bc1e438b465986a8ada354b6332f69e0e3a6/Game/Logic/BehaviorDb.cs#L90)). No supported case-alias path is involved in the registrations checked here.

The target XML range from `Black Cat` (`0x1600`) to `Snowman` (`0x1641`) contains exactly 66 consecutive object descriptors in `EmbeddedData_PermapetsCXML.xml`; there are no holes or unrelated descriptors in the interval ([lower endpoint](https://github.com/kevinbudz/realm-server/blob/bb75bc1e438b465986a8ada354b6332f69e0e3a6/Resources/GameData/EmbeddedData_PermapetsCXML.xml#L17), [upper endpoint](https://github.com/kevinbudz/realm-server/blob/bb75bc1e438b465986a8ada354b6332f69e0e3a6/Resources/GameData/EmbeddedData_PermapetsCXML.xml#L1502), [inclusive range expansion](https://github.com/kevinbudz/realm-server/blob/bb75bc1e438b465986a8ada354b6332f69e0e3a6/Game/Logic/BehaviorDb.cs#L120)). That registration contributes companion behavior coverage, not missing enemy coverage.

The reference has 51 `BehaviorDb.*.cs` files on disk, but the classic project enumerates compile inputs explicitly. It has 48 `logic\\db\\BehaviorDb.*.cs` compile entries. The runtime loader invokes fields whose type is the `_` initializer delegate and whose reflection flags are `NonPublic | Instance` ([reference compile list](https://github.com/ossimc82/fabiano-swagger-of-doom/blob/6fd20aad4a7905b13f25389c68368a942a2b68cb/wServer/wServer.csproj#L154), [later compile entries](https://github.com/ossimc82/fabiano-swagger-of-doom/blob/6fd20aad4a7905b13f25389c68368a942a2b68cb/wServer/wServer.csproj#L217), [reference loader filter](https://github.com/ossimc82/fabiano-swagger-of-doom/blob/6fd20aad4a7905b13f25389c68368a942a2b68cb/wServer/logic/BehaviorDb.cs#L56)). Of the 48 compiled files, 47 contain loader-visible delegate fields; the remaining `BehaviorDb.Nexus.cs` source has only commented-out definitions. One of those 47 fields is the active `Pets` initializer, which registers pet models dynamically by iterating `TypeToPet` ([reference Pets initializer](https://github.com/ossimc82/fabiano-swagger-of-doom/blob/6fd20aad4a7905b13f25389c68368a942a2b68cb/wServer/logic/db/BehaviorDb.Pets.cs#L13), [reference XML `Class=Pet` parser](https://github.com/ossimc82/fabiano-swagger-of-doom/blob/6fd20aad4a7905b13f25389c68368a942a2b68cb/db/data/XmlDatas.cs#L202)). The catalog has 130 such pet descriptors ([reference pet descriptor](https://github.com/ossimc82/fabiano-swagger-of-doom/blob/6fd20aad4a7905b13f25389c68368a942a2b68cb/db/data/Descriptors.cs#L154)); the other 46 fields provide named enemy/object definition groups with 423 IDs. In total, 553 active reference IDs map to 553 distinct object types. The 13 duplicate numeric type pairs in reference XML do not overlap any of these active IDs. `BehaviorDb.CubeGod.cs`, `BehaviorDb.IceCave.cs`, and `BehaviorDb.SkullShrine.cs` are on disk but are not project compile inputs. The active Skull Shrine definition is instead present in compiled `BehaviorDb.Events.cs` ([active Skull Shrine in Events](https://github.com/ossimc82/fabiano-swagger-of-doom/blob/6fd20aad4a7905b13f25389c68368a942a2b68cb/wServer/logic/db/BehaviorDb.Events.cs#L13)). Cube God likewise has a compiled string-ID definition in `BehaviorDb.Cube.cs`; its `_ CubeGod` field has no explicit access modifier but is private by C# class-member default, so it is loader-visible. A separate numeric legacy file is not compiled ([compiled Cube file](https://github.com/ossimc82/fabiano-swagger-of-doom/blob/6fd20aad4a7905b13f25389c68368a942a2b68cb/wServer/wServer.csproj#L222), [active Cube God definition](https://github.com/ossimc82/fabiano-swagger-of-doom/blob/6fd20aad4a7905b13f25389c68368a942a2b68cb/wServer/logic/db/BehaviorDb.Cube.cs#L14), [uncompiled legacy source](https://github.com/ossimc82/fabiano-swagger-of-doom/blob/6fd20aad4a7905b13f25389c68368a942a2b68cb/wServer/logic/db/BehaviorDb.CubeGod.cs#L16)). Therefore source-file counts alone overstate active reference coverage.

## Target ID resolution results

I extracted the first argument of each literal `db.Init` registration in the target database modules, including IDs supplied through literal string arrays, and compared them with object IDs parsed from the target XML catalog. There are 469 named literal registrations; none duplicate another registration name. Exactly one name fails exact XML lookup: `Thessal Dropper`, registered at OceanTrench.cs line 255. It is not present in target GameData; the reference catalog contains that ID as object type `0x1554` ([target registration](https://github.com/kevinbudz/realm-server/blob/bb75bc1e438b465986a8ada354b6332f69e0e3a6/Game/Logic/Database/OceanTrench.cs#L255), [reference object descriptor](https://github.com/ossimc82/fabiano-swagger-of-doom/blob/6fd20aad4a7905b13f25389c68368a942a2b68cb/db/data/dat1.xml#L53248)). Target `Init` returns without storing a model when its object lookup fails; its error message exists only in DEBUG builds ([target failed-lookup path](https://github.com/kevinbudz/realm-server/blob/bb75bc1e438b465986a8ada354b6332f69e0e3a6/Game/Logic/BehaviorDb.cs#L90)). The target also asks the Mermaid Goddess to transform on death into `Thessal Dropper` ([target Thessal behavior](https://github.com/kevinbudz/realm-server/blob/bb75bc1e438b465986a8ada354b6332f69e0e3a6/Game/Logic/Database/OceanTrench.cs#L72)); `TransformOnDeath` returns when its target name cannot resolve ([target transform lookup](https://github.com/kevinbudz/realm-server/blob/bb75bc1e438b465986a8ada354b6332f69e0e3a6/Game/Logic/Behaviors/TransformOnDeath.cs#L20)). This helper chain is ineffective in the checked target catalog. Treat it as an unsupported object/helper in the 2014 catalog unless a same-era data source confirms that it should exist; the later reference does not establish that historical requirement.

The target registration scan found no case-only alias match and no duplicate registration names. These are exact IDs, not resolved by display name or by the lowercased object map. Aside from the out-of-catalog Thessal Dropper entry, the checked literal target registrations resolve to XML object descriptors. The `InitMany` range adds 66 further resolved IDs. Thus the raw registration-name count is 535 and the XML-resolved model-name count is 534; all 66 interval entries are pets rather than enemies. Of the reference's 130 dynamically registered pets, 59 IDs overlap that target range, 10 more are present in target XML but lack target registration, and 61 are absent from target XML. None of the 66 IDs registered by `InitMany` is missing from the target model set.

I also independently checked the expanded coverage inventory's classification counts and type aliases. Its 73 exact target XML-supported gaps all have `target_registered_by_type = false`, and split into 52 `<Enemy/>` entries plus 21 other objects. Its 113 reference-only names all resolve in reference XML, are absent from target XML, and split into 49 reference enemies plus 64 other objects. Ten of the target-supported gaps and 61 of the reference-only names are dynamic reference pets. All 553 active reference IDs resolve to distinct reference object types; none is among the 13 duplicate-type XML alias pairs. The aliases therefore do not create hidden active-definition collisions or invalidate these candidate matches.

## Spawn candidate sanity check

The Candyland comparison in `specialized.md` correctly describes the reference Spoiled Creampuff spawn arithmetic. Reference `Spawn` computes its initial count as `(int)(maxChildren * initialSpawn)` and spawns that many children on state entry ([reference Spawn constructor and entry](https://github.com/ossimc82/fabiano-swagger-of-doom/blob/6fd20aad4a7905b13f25389c68368a942a2b68cb/wServer/logic/behaviors/Spawn.cs#L18)). With `maxChildren: 2, initialSpawn: 2`, the reference definition therefore creates four Big Creampuffs immediately; its stored child count is four, above its cap of two, so later `Spawn` ticks do not add more ([reference Spoiled Creampuff](https://github.com/ossimc82/fabiano-swagger-of-doom/blob/6fd20aad4a7905b13f25389c68368a942a2b68cb/wServer/logic/db/BehaviorDb.CandyLand.cs#L101)). Target Big Creampuff instead runs `SpawnOnce` with cap three, which selects a random one through three children on entry ([target Big Creampuff](https://github.com/kevinbudz/realm-server/blob/bb75bc1e438b465986a8ada354b6332f69e0e3a6/Game/Logic/Database/Candyland.cs#L341), [target SpawnOnce count](https://github.com/kevinbudz/realm-server/blob/bb75bc1e438b465986a8ada354b6332f69e0e3a6/Game/Logic/Behaviors/SpawnOnce.cs#L24)). These are real behavior differences, but the later reference snapshot cannot identify which configuration matches 2014.

## Limits

The source-ID counts above are intended to validate registration and exact target catalog resolution. They do not decide whether later reference-only IDs belong in a 2014 game, and they do not treat an out-of-catalog helper object as a missing behavior for an XML-supported target enemy. The broader encounter inventory should remain the authority for classifying shared versus candidate-only enemy definitions.
