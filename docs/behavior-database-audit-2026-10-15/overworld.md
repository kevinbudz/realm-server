# Overworld enemy database comparison

Target: [`kevinbudz/realm-server`](https://github.com/kevinbudz/realm-server/tree/bb75bc1e438b465986a8ada354b6332f69e0e3a6), HEAD `bb75bc1e438b465986a8ada354b6332f69e0e3a6` (RotMG 7.0.0, 2014).
Reference: [`ossimc82/fabiano-swagger-of-doom`](https://github.com/ossimc82/fabiano-swagger-of-doom/tree/6fd20aad4a7905b13f25389c68368a942a2b68cb), pinned `6fd20aad4a7905b13f25389c68368a942a2b68cb` (2015-11-09).

This compares enemy definitions, not the availability of AI primitives. I excluded named dungeon and event bosses assigned to other audits. Reference files below are compiled by `wServer/wServer.csproj`; `BehaviorDb` discovers and invokes instance fields of type `_` at initialization ([BehaviorDb.cs:41-65](https://github.com/ossimc82/fabiano-swagger-of-doom/blob/6fd20aad4a7905b13f25389c68368a942a2b68cb/wServer/logic/BehaviorDb.cs#L41-L65)). Thus the Highland and shared module entries cited here are active reference definitions, not orphan source files.

I compared ordered non-State constructor calls and their arguments across all shared records in the six matched modules, normalizing legacy names (`coolDown`/`cooldown`, `projectileIndex`/`index`, old loot enums, and positional versus named arguments). I then reviewed the reported differences for gameplay impact. State wrapper nesting was excluded from this mechanical comparison, so this is not a formal proof of graph equivalence where calls otherwise match. The complete matched ID sets are listed under “Shared-body review coverage.”

## Findings

### Highland has no target definitions for 34 reference enemies, including types the target itself schedules in realm population

The target has no Highland database module. This is behaviorally relevant because `Game/Oryx.cs` still schedules Highland enemies in realm terrain populations: `Shield Orc Key`, `Urgle`, and `Undead Dwarf God` at lines 464-470; `Ogre King`, `Dragon Egg`, and `Lizard God` at lines 472-479; and `Minotaur`, `Flayer God`, and `Flamer King` at lines 481-487. The reference Highland implementation registers these types and their behavior/loot (for example `Ogre King` begins at [BehaviorDb.Highland.cs:76](https://github.com/ossimc82/fabiano-swagger-of-doom/blob/6fd20aad4a7905b13f25389c68368a942a2b68cb/wServer/logic/db/BehaviorDb.Highland.cs#L76), `Lizard God` at `:170`, `Flayer God` at `:379`, `Flamer King` at `:425`, `Dragon Egg` at `:492`, `Minotaur` at `:14`, and `Urgle` at `:695`). The reference module is compiled at [wServer.csproj:230](https://github.com/ossimc82/fabiano-swagger-of-doom/blob/6fd20aad4a7905b13f25389c68368a942a2b68cb/wServer/wServer.csproj#L230).

The complete reference-only Highland ID set is: Minotaur; Ogre King, Ogre Warrior, Ogre Mage, Ogre Wizard; Lizard God; Night Elf Archer, Night Elf Warrior, Night Elf Mage, Night Elf Veteran, Night Elf King; Undead Dwarf God, Undead Dwarf Warrior, Undead Dwarf Axebearer, Undead Dwarf Mage, Undead Dwarf King; Soulless Dwarf; Flayer God, Flayer, Flayer Veteran; Flamer King, Flamer; Dragon Egg, White Dragon Whelp, Juvenile White Dragon, Adult White Dragon; Shield Orc Shield, Shield Orc Flooder, Shield Orc Key; Left Horizontal Trap, Top Vertical Trap, 45-225 Diagonal Trap, 135-315 Diagonal Trap; Urgle. Their reference `.Init` lines in the same order are `14, 76, 134, 147, 158, 170, 206, 217, 228, 239, 250, 261, 286, 297, 307, 333, 344, 379, 403, 414, 425, 458, 492, 499, 509, 522, 537, 566, 594, 623, 641, 659, 677, 695`.

**Player-visible consequence:** the target XML coverage confirms these object types exist, and target Oryx population entries schedule a subset in the realm. Those spawned enemies have no server AI model; target entities with no model do not enter behavior states. They therefore cannot run their defined attack, movement, child-spawn, death-transition, or behavior loot logic. This is a high-confidence registration gap. Whether every listed reference-only entry belongs in a strict 2014 restoration is less certain because the reference is from 2015 and includes potentially later content; the Oryx-listed subset is especially strong applicability evidence.

### White Fountain healing semantics differ

Target [Misc.cs:16-18](https://github.com/kevinbudz/realm-server/blob/bb75bc1e438b465986a8ada354b6332f69e0e3a6/Game/Logic/Database/Misc.cs#L16-L18) registers `White Fountain` with `new HealPlayer(5, 1000, 100)` (default heal amount 100). Target [HealPlayer.cs:27-43](https://github.com/kevinbudz/realm-server/blob/bb75bc1e438b465986a8ada354b6332f69e0e3a6/Game/Logic/Behaviors/HealPlayer.cs#L27-L43) iterates all players in range and heals each one whenever its cooldown expires. The pinned reference [BehaviorDb.Misc.cs:13-17](https://github.com/ossimc82/fabiano-swagger-of-doom/blob/6fd20aad4a7905b13f25389c68368a942a2b68cb/wServer/logic/db/BehaviorDb.Misc.cs#L13-L17) uses `NexusHealHp(5, 100, 1000)`. Its implementation ([NexusHealHp.cs:32-42](https://github.com/ossimc82/fabiano-swagger-of-doom/blob/6fd20aad4a7905b13f25389c68368a942a2b68cb/wServer/logic/behaviors/NexusHealHp.cs#L32-L42)) returns when the fountain host has Sick and selects only the nearest player; it heals that player at lines 44-50. The Sick check is on the fountain host, not the selected player.

**Player-visible consequence:** the target fountain heals every nearby player each pulse, including Sick players (the target helper has no Sick check). The reference heals at most one nearby player per pulse and suppresses the pulse when the fountain itself has Sick; it does not check whether the recipient is Sick. This is a high-confidence semantic delta. Which behavior is desired depends on whether 2014 behavior or the 2015 reference is the goal.

### Hobbit Mage no longer drops the Forest Maze portal

Target [Lowland.cs:16-45](https://github.com/kevinbudz/realm-server/blob/bb75bc1e438b465986a8ada354b6332f69e0e3a6/Game/Logic/Database/Lowland.cs#L16-L45) defines the Hobbit Mage’s ring attacks, adds, and loot, but no death portal behavior. Reference [BehaviorDb.Lowland.cs:14-45](https://github.com/ossimc82/fabiano-swagger-of-doom/blob/6fd20aad4a7905b13f25389c68368a942a2b68cb/wServer/logic/db/BehaviorDb.Lowland.cs#L14-L45) adds `DropPortalOnDeath("Forest Maze Portal", 20, PortalDespawnTimeSec: 100)` at line 16 in the same enemy definition.

**Player-visible consequence:** killing a Hobbit Mage cannot produce the Forest Maze portal from this target definition. This is a high-confidence definition difference and a plausible missing gameplay behavior, though the 2015 reference alone does not prove the 2014 design intended the same portal drop.

### Common realm-god loot policy and reproduction differs across nine shared Mountain IDs

For **White Demon, Sprite God, Medusa, Ent God, Beholder, Flying Brain, Slime God, Ghost God, and Djinn**, the target adds density-limited `Reproduce` and moves the high-tier equipment loot beneath a 1% damage threshold. The target also removes the reference Common/Uncommon egg drops; it changes each god's potion threshold to 7% and usually raises potion chance to 7%. The pinned reference keeps equipment loot outside its threshold group and places a 1%–1.5% potion plus Common/Uncommon eggs behind an 18% group threshold. This is a consistent set-wide loot policy change, not a one-off White Demon discrepancy.

Evidence: target records begin at `[Mountain.cs:49](https://github.com/kevinbudz/realm-server/blob/bb75bc1e438b465986a8ada354b6332f69e0e3a6/Game/Logic/Database/Mountain.cs#L49), 72, 103, 128, 149, 172, 194, 216, 323`; their reproduction and threshold groups are visible at lines `57-68`, `79-92`, `112-125`, `135-146`, `157-169`, `179-191`, `202-213`, `223-234`, and `330` onward respectively. Reference records begin at `[BehaviorDb.Mountain.cs:14](https://github.com/ossimc82/fabiano-swagger-of-doom/blob/6fd20aad4a7905b13f25389c68368a942a2b68cb/wServer/logic/db/BehaviorDb.Mountain.cs#L14), 74, 108, 134, 181, 206, 229, 252, 350`; the repeated 18% group and egg drops are exemplified at lines `31-35`, `92-95`, and `128-131`, with matching groups in the other listed god entries.

**Player-visible consequence:** target gods can replenish nearby population until their `densityMax` cap (typically three; two for Slime God), while players need to deal 1% damage to qualify for target equipment drops; reference equipment has no such added threshold. Target god definitions omit the reference egg drops and alter potion eligibility/chance. This is a high-confidence semantic delta, but not necessarily a defect because the source dates differ.

### Leviathan has a different attack cycle and reward gate

Target [Mountain.cs:401-438](https://github.com/kevinbudz/realm-server/blob/bb75bc1e438b465986a8ada354b6332f69e0e3a6/Game/Logic/Database/Mountain.cs#L401-L438) has a `Wander` opening with swirl and a two-shot pattern, then a three-state `Triangle` phase that moves along fixed lines and fires four angular volleys in each segment (`:402-430`). It returns to `Wander` after the triangle. Reference [BehaviorDb.Mountain.cs:487-547](https://github.com/ossimc82/fabiano-swagger-of-doom/blob/6fd20aad4a7905b13f25389c68368a942a2b68cb/wServer/logic/db/BehaviorDb.Mountain.cs#L487-L547) uses a `pattern walk` phase with alternating stay-back, orbit, and follow movement (`:489-508`), three triangular bursts (`:509-527`), then a separate `follow` phase with staggered predictive shots (`:529-542`). The target gates Defense Potion, weapon, and health/magic potions under a 1% loot threshold; reference has a 1% weapon chance and 4%/1% health/magic potion chances as direct loot entries (`:432-437` vs `:544-546`).

**Player-visible consequence:** Leviathan's movement rhythm, bullet formations, and pursuit window differ substantially, and low-damage eligibility for its potions changes. High confidence that these are real differences; the 2015 fight should not automatically be treated as the desired 2014 version.

### Portal-drop chances and portal availability differ across ordinary realm enemies

The target's `DropPortalOnDeath` takes a probability fraction and defaults portal timeout to 30 seconds (`[DropPortalOnDeath.cs:11-16](https://github.com/kevinbudz/realm-server/blob/bb75bc1e438b465986a8ada354b6332f69e0e3a6/Game/Logic/Behaviors/DropPortalOnDeath.cs#L11-L16), 31-36`); the reference takes an integer percent and these definitions explicitly request 100 seconds (`[DropPortalOnDeath.cs:21-42](https://github.com/ossimc82/fabiano-swagger-of-doom/blob/6fd20aad4a7905b13f25389c68368a942a2b68cb/wServer/logic/behaviors/DropPortalOnDeath.cs#L21-L42), 49-67`). Consequently, many equivalent-looking calls are not numerically equivalent:

- In Lowland and Shore, target gives a **1% Pirate Cave Portal chance** to Goblin Warrior, Forest Nymph, Giant Crab, Sand Devil, and the three Gelatinous Cubes (`[Lowland.cs:298](https://github.com/kevinbudz/realm-server/blob/bb75bc1e438b465986a8ada354b6332f69e0e3a6/Game/Logic/Database/Lowland.cs#L298), 377, 456, 479`; `Shore.cs:150, 158, 166`). Reference uses **20% and 100 seconds** for the same seven enemies (`BehaviorDb.Lowland.cs:309, 397, 457, 510`; `BehaviorDb.Shore.cs:159, 169, 179`).
- Reference adds **20% Forest Maze Portal drops** for Hobbit Mage, Elf Wizard, Goblin Mage, and Enraged Bunny (`BehaviorDb.Lowland.cs:16, 213, 329, 372`); those target definitions (`Lowland.cs:16, 198, 301, 339`) contain no corresponding portal behavior.
- Reference adds **20% Forest Maze Portal drops** for Wasp Queen, Dwarf King, and Drake Baby (`BehaviorDb.Midland.cs:172, 469, 642`); target entries begin at `Midland.cs:151, 425, 590` and have no portal drop. Target instead adds **10% Spider Den Portal drops** to Orc King and Werelion (`Midland.cs:47, 453`), which are absent from their reference entries (`BehaviorDb.Midland.cs:50, 497`).
- Target adds a **17% Abyss of Demons Portal** drop to White Demon; the reference White Demon entry has no portal drop (`Mountain.cs:50`; [BehaviorDb.Mountain.cs:14-35](https://github.com/ossimc82/fabiano-swagger-of-doom/blob/6fd20aad4a7905b13f25389c68368a942a2b68cb/wServer/logic/db/BehaviorDb.Mountain.cs#L14-L35)). Flying Brain and Ghost God retain the same portal destinations, but target reduces their chances from 20% to 17% (`Mountain.cs:180, 224`; `BehaviorDb.Mountain.cs:214, 260`). Those reference calls use the helper default 30-second expiry. Medusa changes destination and chance: target gives Snake Pit at 17% (`Mountain.cs:104`), while reference gives Abyss of Demons at 20% ([BehaviorDb.Mountain.cs:117](https://github.com/ossimc82/fabiano-swagger-of-doom/blob/6fd20aad4a7905b13f25389c68368a942a2b68cb/wServer/logic/db/BehaviorDb.Mountain.cs#L117)). Target Sprite Child uses 11% Glowing Portal versus reference 20% (`Mountain.cs:101`; [BehaviorDb.Mountain.cs:105](https://github.com/ossimc82/fabiano-swagger-of-doom/blob/6fd20aad4a7905b13f25389c68368a942a2b68cb/wServer/logic/db/BehaviorDb.Mountain.cs#L105)). Arena Headless Horseman preserves the 40% rate but target's implicit 30-second expiry differs from reference's 100-second override (`Mountain.cs:47`; [BehaviorDb.Mountain.cs:71](https://github.com/ossimc82/fabiano-swagger-of-doom/blob/6fd20aad4a7905b13f25389c68368a942a2b68cb/wServer/logic/db/BehaviorDb.Mountain.cs#L71)).

**Player-visible consequence:** where the target rate is 1% versus 20%, the corresponding dungeon portal appears far less often; target portals also expire sooner where the reference explicitly grants 100 seconds. Several target enemies lose the reference portal entirely, while Orc King and Werelion gain a different portal path; White Demon gains a portal absent from the reference entry. These are high-confidence semantic deltas. Whether the target's lower rates or changed destinations are intentional balance/content choices needs historical confirmation.

### Remaining shared-body differences

- **Elf Swordsman:** target `new Buzz(1, dist: 1)` (`Lowland.cs:251`) has no pause parameter. Reference uses `new Buzz(1, 1, 2000)` ([BehaviorDb.Lowland.cs:270](https://github.com/ossimc82/fabiano-swagger-of-doom/blob/6fd20aad4a7905b13f25389c68368a942a2b68cb/wServer/logic/db/BehaviorDb.Lowland.cs#L270)). The reference Buzz constructor accepts a 2,000 ms argument, but that value is unused in the active behavior; neither implementation inserts a rest between dashes ([reference Buzz.cs:17-48](https://github.com/ossimc82/fabiano-swagger-of-doom/blob/6fd20aad4a7905b13f25389c68368a942a2b68cb/wServer/logic/behaviors/Buzz.cs#L17-L48), [target Buzz.cs:17-50](https://github.com/kevinbudz/realm-server/blob/bb75bc1e438b465986a8ada354b6332f69e0e3a6/Game/Logic/Behaviors/Buzz.cs#L17-L50)). The parameter alone does not establish a movement-timing difference.
- **Arena Headless Horseman:** target returns at speed 1.5 (`Mountain.cs:30`); reference `ReturnToSpawn()` defaults to speed 2 ([BehaviorDb.Mountain.cs:54](https://github.com/ossimc82/fabiano-swagger-of-doom/blob/6fd20aad4a7905b13f25389c68368a942a2b68cb/wServer/logic/db/BehaviorDb.Mountain.cs#L54); `behaviors/ReturnToSpawn.cs:18-21`). The retreat is slower in target. The portal chance is otherwise 40% in both, with the timeout discrepancy documented above.
- **Sprite God:** target adds density-limited reproduction and uses `ReproduceChildren(5, 0.5, cooldown: 5000)` (`Mountain.cs:79-80`); reference uses a one-time `Spawn("Sprite Child", 5)` ([BehaviorDb.Mountain.cs:82](https://github.com/ossimc82/fabiano-swagger-of-doom/blob/6fd20aad4a7905b13f25389c68368a942a2b68cb/wServer/logic/db/BehaviorDb.Mountain.cs#L82)). Target tracks living children and replenishes below five after cooldown ([ReproduceChildren.cs:47-84](https://github.com/kevinbudz/realm-server/blob/bb75bc1e438b465986a8ada354b6332f69e0e3a6/Game/Logic/Behaviors/ReproduceChildren.cs#L47-L84)), while reference Spawn increments a lifetime count and does not decrement it when children die (`behaviors/Spawn.cs:26-63`). Target Sprite God can sustain child waves; reference generally stops replacing children after it has spawned its quota. High confidence.
- **Paper Bot / Steel Bot / Rock Bot:** target adds loot thresholds and drops to these bots (`Mountain.cs:251-263, 285-320`) where the reference entries only define behavior (for example [BehaviorDb.Mountain.cs:275-355](https://github.com/ossimc82/fabiano-swagger-of-doom/blob/6fd20aad4a7905b13f25389c68368a942a2b68cb/wServer/logic/db/BehaviorDb.Mountain.cs#L275-L355)). Paper Bot also gains a 15% Puppet Theatre portal (`Mountain.cs:267`). Target's `HealGroup` calls correspond to reference `Heal` calls for the same groups (`Mountain.cs:247, 277, 305`; `BehaviorDb.Mountain.cs:285, 311, 336`); both implementations heal all nearby members to full, so that rename is not a material difference. Target-only drops and portal are real additions, with applicability/balance intent unclear.
- **Scorpion Queen:** target adds `ChangeSize(100, 200)` (`Shore.cs:50-52`); reference has no size-change call in its definition ([BehaviorDb.Shore.cs:56-65](https://github.com/ossimc82/fabiano-swagger-of-doom/blob/6fd20aad4a7905b13f25389c68368a942a2b68cb/wServer/logic/db/BehaviorDb.Shore.cs#L56-L65)). Target queen visibly grows to size 200. This is a lower-impact presentation difference.
- **Orc Queen:** target `HealGroup(10, "OrcKings", 300)` (`Midland.cs:71`) corresponds to reference `Heal(10, "OrcKings", 300)` ([BehaviorDb.Midland.cs:77](https://github.com/ossimc82/fabiano-swagger-of-doom/blob/6fd20aad4a7905b13f25389c68368a942a2b68cb/wServer/logic/db/BehaviorDb.Midland.cs#L77)). Both implementations heal every matching enemy in range to full (`HealGroup.cs:31-59`; `behaviors/Heal.cs:61-93`), so the API rename preserves behavior.
- **Oasis:** all five shared definitions have matching normalized constructor calls and parameters. No material difference was found in the sweep.
- **Other checked shared IDs:** all matching records in Lowland, Midland, Mountain, and Shore not called out above had matching non-State constructor sequences/arguments after normalizing old keyword and API spellings. `State` nesting was not used as proof of exact control-flow identity.
