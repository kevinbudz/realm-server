## Scope and confidence

Target: [`kevinbudz/realm-server`](https://github.com/kevinbudz/realm-server/tree/bb75bc1e438b465986a8ada354b6332f69e0e3a6) at `bb75bc1e438b465986a8ada354b6332f69e0e3a6` (work branch). Reference data comes only from database modules included in `wServer/wServer.csproj`; in particular, `BehaviorDb.IceCave.cs` exists in the checkout but is excluded from that project, so it is not counted as active reference behavior. This comparison establishes differences between these two snapshots. The reference README identifies its base as RotMG build 27.5-era, so whether a difference applied to 2014 version 7.0.0 is unverified.

This pass compares the requested encounter database modules and principal boss/minion logic; it does not claim line-by-line verification of every ordinary mob or every drop table. IDs below are the exact behavior registrations extracted from the named modules. Davy Jones is deferred to the boss comparison; Candyland, Shatters, and Oryx are out of scope. The coverage agent is doing the exhaustive target/reference registration audit.

## Material semantic differences

### Abyss: Malphas uses a different encounter and adds two minion types

The reference Malphas wakes at 8 tiles, reproduces at most one missile, then runs 10-second basic/small/big attack sections separated by brief shrink/grow/normalize invulnerability windows ([BehaviorDb.Abyss.cs:10-70](https://github.com/ossimc82/fabiano-swagger-of-doom/blob/6fd20aad4a7905b13f25389c68368a942a2b68cb/wServer/logic/db/BehaviorDb.Abyss.cs#L10-L70); later attack transitions at `:46-72`). Its registered IDs include Archdemon Malphas, Malphas Missile, and six demon/brute enemy types (`:10-12`, `:82`, `:104-211`).

The target Malphas wakes at 11 tiles, reproduces up to three Malphas Protectors, adds a missile cycle with explicit two/four-second vulnerability windows, then proceeds through small-shot, three-step large rotation, and Malphas Flamer sections ([Abyss.cs:42-66](https://github.com/kevinbudz/realm-server/blob/bb75bc1e438b465986a8ada354b6332f69e0e3a6/Game/Logic/Database/Abyss.cs#L42-L66), `:76-114`, `:125-157`). Target-only registrations are `Malphas Protector` and `Malphas Flamer` (`:16`, `:214`); these IDs are absent from every reference runtime DB file. Target additionally defines protector shield/shot behavior and flamer charge/explosion behavior ([Abyss.cs:16-23](https://github.com/kevinbudz/realm-server/blob/bb75bc1e438b465986a8ada354b6332f69e0e3a6/Game/Logic/Database/Abyss.cs#L16-L23), `:214-243`). Target adds a Realm Portal drop and revised tier/potion table ([Abyss.cs:141-159](https://github.com/kevinbudz/realm-server/blob/bb75bc1e438b465986a8ada354b6332f69e0e3a6/Game/Logic/Database/Abyss.cs#L141-L159)); reference applies the `AbyssDeath` setpiece on death and has its own tier table ([BehaviorDb.Abyss.cs:12](https://github.com/ossimc82/fabiano-swagger-of-doom/blob/6fd20aad4a7905b13f25389c68368a942a2b68cb/wServer/logic/db/BehaviorDb.Abyss.cs#L12), `:59-78`). **High confidence on behavioral difference; historical applicability remains unknown.**

### Pirate Cave: common boss loop aligns; target adds portal and key loot

All 14 object IDs appear in both modules. Dreadstump’s wait-for-player trigger, stay-near-spawn movement, two shots on 2,000/1,000 ms cooldowns, and taunt match structurally ([BehaviorDb.PirateCave.cs:14-41](https://github.com/ossimc82/fabiano-swagger-of-doom/blob/6fd20aad4a7905b13f25389c68368a942a2b68cb/wServer/logic/db/BehaviorDb.PirateCave.cs#L14-L41); [PirateCave.cs:16-44](https://github.com/kevinbudz/realm-server/blob/bb75bc1e438b465986a8ada354b6332f69e0e3a6/Game/Logic/Database/PirateCave.cs#L16-L44)). Target adds `DropPortalOnDeath("Realm Portal", ...)` and a `Pirate Cave Key` drop threshold ([PirateCave.cs:17](https://github.com/kevinbudz/realm-server/blob/bb75bc1e438b465986a8ada354b6332f69e0e3a6/Game/Logic/Database/PirateCave.cs#L17), `:33`); the reference Dreadstump definition has neither. Other trash IDs match, but full trash loot tables were not exhaustively compared.

### Snake Pit: Stheno’s eight blast states align; portal drop differs

Both modules register the same 15 IDs. Stheno uses the same player-within-20 trigger, eight one-second silver-blast states, invulnerability alternation, then swarm reproduction and another timed blast sequence ([BehaviorDb.SnakePit.cs:15-90](https://github.com/ossimc82/fabiano-swagger-of-doom/blob/6fd20aad4a7905b13f25389c68368a942a2b68cb/wServer/logic/db/BehaviorDb.SnakePit.cs#L15-L90); [SnakePit.cs:16-89](https://github.com/kevinbudz/realm-server/blob/bb75bc1e438b465986a8ada354b6332f69e0e3a6/Game/Logic/Database/SnakePit.cs#L16-L89)). The target uses the renamed `index`/`cooldown` arguments but preserves the same observed values. The reference root state includes `RealmPortalDrop()` ([BehaviorDb.SnakePit.cs:17](https://github.com/ossimc82/fabiano-swagger-of-doom/blob/6fd20aad4a7905b13f25389c68368a942a2b68cb/wServer/logic/db/BehaviorDb.SnakePit.cs#L17)); the target root begins directly with `Idle` and does not attach a portal drop ([SnakePit.cs:16-20](https://github.com/kevinbudz/realm-server/blob/bb75bc1e438b465986a8ada354b6332f69e0e3a6/Game/Logic/Database/SnakePit.cs#L16-L20)). This may affect portal behavior on death; confirm the target’s separate map/portal flow before calling it a player-visible regression. **High confidence on source difference.**

### Undead Lair: Septavius loop and reference coverage differ substantially

The active reference module registers Septavius and only three Septavius ghosts ([BehaviorDb.UndeadLair.cs:15](https://github.com/ossimc82/fabiano-swagger-of-doom/blob/6fd20aad4a7905b13f25389c68368a942a2b68cb/wServer/logic/db/BehaviorDb.UndeadLair.cs#L15), `:458`, `:474`, `:490`). Septavius cycles through repeating fixed-angle 3-shot fans at 150 ms intervals (the first fan starts at 0 degrees and advances by 18 degrees), plus a projectile-index-3 shot on a 1,000 ms cooldown ([BehaviorDb.UndeadLair.cs:20-25](https://github.com/ossimc82/fabiano-swagger-of-doom/blob/6fd20aad4a7905b13f25389c68368a942a2b68cb/wServer/logic/db/BehaviorDb.UndeadLair.cs#L20-L25), `:90-107`). It does not define the target’s Lair Ghost Archer/Knight/etc. IDs anywhere in active reference DB files.

The target instead starts Septavius invulnerable, waits 3 seconds after the 8-tile player trigger, then cycles through four 10-second phases: `spiral` spawns six Lair ghost types while firing five offset three-shot fans; `ring` fires 12; `quiet` fires two rings and a spread; `spawn` reproduces the three named Septavius ghosts ([UndeadLair.cs:16-73](https://github.com/kevinbudz/realm-server/blob/bb75bc1e438b465986a8ada354b6332f69e0e3a6/Game/Logic/Database/UndeadLair.cs#L16-L73)). Target registers 35 names total; 31 are absent from active reference DB content, including its Lair trash, traps, and construct/mummy/slime families ([UndeadLair.cs:87-400](https://github.com/kevinbudz/realm-server/blob/bb75bc1e438b465986a8ada354b6332f69e0e3a6/Game/Logic/Database/UndeadLair.cs#L87-L400); active reference exact-ID search found no matches). The target loot block for Septavius includes Wisdom, Doom Bow, Wine Cellar Incantation, and tier loot (`:74-85`), while the reference drops are in the same boss definition but could not be fully compared in this pass. **High confidence on encounter and registration differences.**

### Sprite World: Limon begins and cycles differently

Both register the same 11 IDs. Reference Limon starts with an idle wander/flash state and transitions at 12 tiles to `nothing`; its follow-on `e.e` and `:c` states shoot projectile 0 every 300 ms, transition after 3/7 seconds, then return to spawn/invulnerability and toss four elements ([BehaviorDb.SpriteWorld.cs:10-20](https://github.com/ossimc82/fabiano-swagger-of-doom/blob/6fd20aad4a7905b13f25389c68368a942a2b68cb/wServer/logic/db/BehaviorDb.SpriteWorld.cs#L10-L20), `:22-44`, `:45-67`).

Target Limon starts invulnerable and waits for a player within 11 tiles; it then moves through named teleport, circle-player, not-moving/boom, and subsequent attack states ([SpriteWorld.cs:77-112](https://github.com/kevinbudz/realm-server/blob/bb75bc1e438b465986a8ada354b6332f69e0e3a6/Game/Logic/Database/SpriteWorld.cs#L77-L112), continuing through later states in that definition). This is a material trigger and phase-structure change rather than a naming-only port. Both retain the four Limon Element IDs; their element behaviors were not individually compared here. **High confidence on phase difference.**

### Spider Den: Arachna’s web and attack structure are aligned

Both versions wait invulnerable until a player is within 12 tiles, toss the same nine web spokes in the same positions, wait 2 seconds, then wander and use the same three-shot pattern on projectiles 0/1 ([BehaviorDb.SpiderDen.cs:10-36](https://github.com/ossimc82/fabiano-swagger-of-doom/blob/6fd20aad4a7905b13f25389c68368a942a2b68cb/wServer/logic/db/BehaviorDb.SpiderDen.cs#L10-L36); [SpiderDen.cs:16-41](https://github.com/kevinbudz/realm-server/blob/bb75bc1e438b465986a8ada354b6332f69e0e3a6/Game/Logic/Database/SpiderDen.cs#L16-L41)). Target loot includes the same three named items and Healing Ichor threshold (`:42-47`), matching the reference entries ([BehaviorDb.SpiderDen.cs:38-44](https://github.com/ossimc82/fabiano-swagger-of-doom/blob/6fd20aad4a7905b13f25389c68368a942a2b68cb/wServer/logic/db/BehaviorDb.SpiderDen.cs#L38-L44)). No material boss-phase difference found in the reviewed block.

### Tomb: expanded registration set; boss threshold/phase deltas need careful interpretation

Reference registers the three Tomb bosses, three pyramid artifacts, three statues, Inactive/Active Sarcophagus, Scarab, and Tomb Boss Anchor (13 total) ([BehaviorDb.Tomb.cs:13](https://github.com/ossimc82/fabiano-swagger-of-doom/blob/6fd20aad4a7905b13f25389c68368a942a2b68cb/wServer/logic/db/BehaviorDb.Tomb.cs#L13), `:97`, `:145`, `:179-201`, `:203-258`, `:260`, `:279`, `:292`, `:321`). Target has these shared entities plus 18 additional registrations: three Sphinx artifacts, three Nile artifacts, Eagle Sentry, Bloated Mummy, Lion Archer, Jackal Warrior/Assassin/Veteran/Lord, Beam Priest/Priestess, and three turrets ([Tomb.cs:16](https://github.com/kevinbudz/realm-server/blob/bb75bc1e438b465986a8ada354b6332f69e0e3a6/Game/Logic/Database/Tomb.cs#L16), `:427-483`, `:595`, `:606`, `:618`, `:633-679`, `:680`, `:687`, `:741`, `:795`, `:849`). These additions are not present in active reference behavior DB files.

At the shared bosses, both versions use the same `Tomb Boss Anchor` and their three boss loops orbit it, but the phase progressions are not equivalent:

- **Defender:** Reference transitions at HP `.99 → .97 → .9 → .66 → .5 → .33 → .1` across weakning, active, boomerang, double shot, artifacts, triple shot, and rage ([BehaviorDb.Tomb.cs:13-80](https://github.com/ossimc82/fabiano-swagger-of-doom/blob/6fd20aad4a7905b13f25389c68368a942a2b68cb/wServer/logic/db/BehaviorDb.Tomb.cs#L13-L80)). Target uses `.989 → .979 → .7 → .55 → .4 → .25 → .06` and adds five explicit 3-second invulnerability windows, including two artifact phases ([Tomb.cs:16-119](https://github.com/kevinbudz/realm-server/blob/bb75bc1e438b465986a8ada354b6332f69e0e3a6/Game/Logic/Database/Tomb.cs#L16-L119)). Projectile counts and cooldowns also change: reference active uses projectile 2/1/0 at 8/4/6 shots with 1,000/3,000/3,100 ms cooldowns (`:27-32`); target uses 8/3/5 with 1,000/5,000/5,000 ms ([Tomb.cs:35-41](https://github.com/kevinbudz/realm-server/blob/bb75bc1e438b465986a8ada354b6332f69e0e3a6/Game/Logic/Database/Tomb.cs#L35-L41)).
- **Support:** Reference has idle, weakning, active, boomerang, then a rage state; the `.66` transition to `double shot` is commented out ([BehaviorDb.Tomb.cs:97-128](https://github.com/ossimc82/fabiano-swagger-of-doom/blob/6fd20aad4a7905b13f25389c68368a942a2b68cb/wServer/logic/db/BehaviorDb.Tomb.cs#L97-L128)). Target adds shield intervals and continues through paralyze, artifacts, double shoot, and rage at `.9/.7/.5/.3/.06`, spawning Sphinx Artifact 1 during the artifact phases ([Tomb.cs:128-232](https://github.com/kevinbudz/realm-server/blob/bb75bc1e438b465986a8ada354b6332f69e0e3a6/Game/Logic/Database/Tomb.cs#L128-L232)).
- **Attacker:** Reference’s only transition after weakning is commented out, so its active attack phases are unreachable from weakning; its `rage` state likewise has no incoming transition ([BehaviorDb.Tomb.cs:145-161](https://github.com/ossimc82/fabiano-swagger-of-doom/blob/6fd20aad4a7905b13f25389c68368a942a2b68cb/wServer/logic/db/BehaviorDb.Tomb.cs#L145-L161)). Target supplies the missing progression (`.988 → .9788 → .72 → .675 → .4 → .2 → .06`) and adds alternating grenade states, repeated 3-second invulnerability windows, Scarab spawns, and Nile Artifact 1 ([Tomb.cs:240-419](https://github.com/kevinbudz/realm-server/blob/bb75bc1e438b465986a8ada354b6332f69e0e3a6/Game/Logic/Database/Tomb.cs#L240-L419)).

The three bosses’ drops also differ. Reference uses a `.32` Potion of Life threshold, `.1` unique-item threshold (Defender: Ring of the Pyramid/Tome of Holy Protection/Wine Cellar Incantation at `.005` each; Support: Ring of the Sphinx and incantation at `.005`; Attacker: Ring of the Nile and incantation at `.002`), plus `.2` egg thresholds ([BehaviorDb.Tomb.cs:82-95](https://github.com/ossimc82/fabiano-swagger-of-doom/blob/6fd20aad4a7905b13f25389c68368a942a2b68cb/wServer/logic/db/BehaviorDb.Tomb.cs#L82-L95), `:130-142`, `:163-175`). Target uses a `.01` threshold with Potion of Life at 1, corresponding ring at `.04`, and Wine Cellar Incantation at `.05`; Defender also has Tome of Holy Protection at `.01` ([Tomb.cs:121-125](https://github.com/kevinbudz/realm-server/blob/bb75bc1e438b465986a8ada354b6332f69e0e3a6/Game/Logic/Database/Tomb.cs#L121-L125), `:234-238`, `:420-424`). The target definitions omit the reference egg thresholds. These are source-tree differences; exact runtime loot semantics depend on each branch’s loot engine.
### Lord of the Lost Lands: target rewrites startup and completion flow

All four IDs are shared. Reference waits for a player within 8 tiles, then alternates four directional 7-shot attacks for 8.5 seconds, gathers for 5.75 seconds, tosses four guardians, creates eight protection crystals, and returns to startup once crystals disappear; it also has a 15% HP loss finale and self-destruct ([BehaviorDb.Lotll.cs:18-80](https://github.com/ossimc82/fabiano-swagger-of-doom/blob/6fd20aad4a7905b13f25389c68368a942a2b68cb/wServer/logic/db/BehaviorDb.Lotll.cs#L18-L80)). The target instead starts in `Waiting` until the boss has lost 1% HP, opens with two 7-shot lines and repeated Guardian tosses, uses random choice between Attack patterns and a follow-player state, then runs a Gathering/Protection loop ([LotLL.cs:16-134](https://github.com/kevinbudz/realm-server/blob/bb75bc1e438b465986a8ada354b6332f69e0e3a6/Game/Logic/Database/LotLL.cs#L16-L134)).

The reference module explicitly drops an `Ice Cave Portal` on death ([BehaviorDb.Lotll.cs:20](https://github.com/ossimc82/fabiano-swagger-of-doom/blob/6fd20aad4a7905b13f25389c68368a942a2b68cb/wServer/logic/db/BehaviorDb.Lotll.cs#L20)); target’s boss definition does not include a portal drop in the reviewed definition, and its completion proceeds through a `Dead` state to `Suicide` ([LotLL.cs:99-109](https://github.com/kevinbudz/realm-server/blob/bb75bc1e438b465986a8ada354b6332f69e0e3a6/Game/Logic/Database/LotLL.cs#L99-L109)).
