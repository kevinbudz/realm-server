# Review and validation notes

This file records interpretation checks that affect how the detailed comparisons should be read. It is not a separate behavior audit.

- Spawn counts depend on each primitive's constructor semantics. `initialSpawn` is a multiplier of `maxChildren` in both [target Spawn](https://github.com/kevinbudz/realm-server/blob/bb75bc1e438b465986a8ada354b6332f69e0e3a6/Game/Logic/Behaviors/Spawn.cs#L14) and [reference Spawn](https://github.com/ossimc82/fabiano-swagger-of-doom/blob/6fd20aad4a7905b13f25389c68368a942a2b68cb/wServer/logic/behaviors/Spawn.cs#L18). For candidate Spoiled Creampuff, `maxChildren: 2, initialSpawn: 2` therefore requests four initial children; its counter starts above the cap and subsequent Spawn emissions stop. Target Big Creampuff uses [SpawnOnce(maxChildren: 3)](https://github.com/kevinbudz/realm-server/blob/bb75bc1e438b465986a8ada354b6332f69e0e3a6/Game/Logic/Behaviors/SpawnOnce.cs#L24), which selects a random one to three children once. Candidate Big Creampuff's `maxChildren: 2, initialSpawn: 0.5` computes one initial child; successful initial entry increments the counter to the cap, so the cooldown does not add another, even after that child dies. See the [specialized comparison](specialized.md#candyland) for the corresponding enemy definitions.
- Cube God required resolving which reference definition is active. The reference project compiles `BehaviorDb.Cube.cs`, excludes `BehaviorDb.CubeGod.cs`, and the loader reflects nonpublic instance fields. Both XML catalogs identify Cube God as type `0x0d59`; the compiled `Cube.cs` initializer is the active definition for that ID. The [boss comparison](bosses.md#realm-event-bosses) records the resulting spawn and loot differences.
- Reference-only XML IDs and target XML IDs without behavior registrations are separate findings. The former establishes candidate-only catalog coverage; it does not prove a historical gap in 2014. The latter establishes a missing behavior registration for an object in the target's own catalog, subject to the extraction's exact-name and `InitMany` rules.
- No runtime simulation or exhaustive semantic parity test is claimed. Phase and loot findings are source comparisons, and their historical correctness remains uncertain where only the 2015 candidate differs.
