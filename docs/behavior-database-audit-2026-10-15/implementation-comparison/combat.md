# Combat behavior implementation comparison

Compared target [`bb75bc1e438b465986a8ada354b6332f69e0e3a6`](https://github.com/kevinbudz/realm-server/tree/bb75bc1e438b465986a8ada354b6332f69e0e3a6) with reference [`6fd20aad4a7905b13f25389c68368a942a2b68cb`](https://github.com/ossimc82/fabiano-swagger-of-doom/tree/6fd20aad4a7905b13f25389c68368a942a2b68cb) (2015-11-09). This note focuses on shared combat primitives; it is not a full projectile/network engine audit and does not establish historical intent. Source links are pinned to these revisions.

## Most direct answer: the target can fire one server tick sooner

Both `Shoot` implementations reset their cooldown after attempting a volley, including when no target was in range, and both interpret cooldown values as milliseconds. Their loop ordering differs:

- Target subtracts `MillisecondsPerTick` and then tests `<= 0` ([target Shoot](https://github.com/kevinbudz/realm-server/blob/bb75bc1e438b465986a8ada354b6332f69e0e3a6/Game/Logic/Behaviors/Shoot.cs#L64-L75), reset at [lines 142–145](https://github.com/kevinbudz/realm-server/blob/bb75bc1e438b465986a8ada354b6332f69e0e3a6/Game/Logic/Behaviors/Shoot.cs#L142)).
- Reference tests whether the stored cooldown is already `<= 0`; if positive it only subtracts the current tick and cannot fire until a subsequent tick ([reference Shoot](https://github.com/ossimc82/fabiano-swagger-of-doom/blob/6fd20aad4a7905b13f25389c68368a942a2b68cb/wServer/logic/behaviors/Shoot.cs#L65-L79), decrement/reset at [lines 117–123](https://github.com/ossimc82/fabiano-swagger-of-doom/blob/6fd20aad4a7905b13f25389c68368a942a2b68cb/wServer/logic/behaviors/Shoot.cs#L117)).

For a positive post-shot cooldown `C` and fixed tick size `d`, this gives target interval `ceil(C/d) × d`; reference interval `(ceil(C/d) + 1) × d`. That is an extra server tick per repeat in the reference, not a cooldown normalization mismatch. At equal tick rates, the target repeats one tick earlier for positive cooldowns.

The checked runtime defaults make a real same-definition example concrete. The target settings file specifies 10 ticks/second (100ms per tick: [Settings.xml](https://github.com/kevinbudz/realm-server/blob/bb75bc1e438b465986a8ada354b6332f69e0e3a6/Settings.xml#L8), [Settings.cs](https://github.com/kevinbudz/realm-server/blob/bb75bc1e438b465986a8ada354b6332f69e0e3a6/Common/Settings.cs#L63-L65)). The reference server reads `tps` with a default of 20 ([Program.cs](https://github.com/ossimc82/fabiano-swagger-of-doom/blob/6fd20aad4a7905b13f25389c68368a942a2b68cb/wServer/Program.cs#L47-L49)); its logic ticker uses `1000/TPS` milliseconds ([LogicTicker.cs](https://github.com/ossimc82/fabiano-swagger-of-doom/blob/6fd20aad4a7905b13f25389c68368a942a2b68cb/wServer/realm/LogicTicker.cs#L25-L34)). The reference TPS is configurable, so the comparison is conditional on those checked settings/defaults.

`Brown Den Spider` has the same three-shot, 20-degree, projectile-index-0, 500ms behavior on each side ([target definition](https://github.com/kevinbudz/realm-server/blob/bb75bc1e438b465986a8ada354b6332f69e0e3a6/Game/Logic/Database/SpiderDen.cs#L139-L145), [reference definition](https://github.com/ossimc82/fabiano-swagger-of-doom/blob/6fd20aad4a7905b13f25389c68368a942a2b68cb/wServer/logic/db/BehaviorDb.SpiderDen.cs#L157-L165)). Starting after the first shot, target repeats every 500ms; reference repeats every 550ms. This is 2 volleys/s versus about 1.82 volleys/s, so the target produces 10% more volleys per second for this attack. A same-config counterexample shows why the result is not a global rate multiplier: `Beholder` has a 750ms five-shot attack on both sides ([target](https://github.com/kevinbudz/realm-server/blob/bb75bc1e438b465986a8ada354b6332f69e0e3a6/Game/Logic/Database/Mountain.cs#L149-L157), [reference](https://github.com/ossimc82/fabiano-swagger-of-doom/blob/6fd20aad4a7905b13f25389c68368a942a2b68cb/wServer/logic/db/BehaviorDb.Mountain.cs#L181-L190)); both resolve to 800ms with these tick sizes.

A zero cooldown parameter is normalized to 1000ms by both APIs: target calls `NormalizeCooldown(cooldown, 1000)` ([Shoot constructor](https://github.com/kevinbudz/realm-server/blob/bb75bc1e438b465986a8ada354b6332f69e0e3a6/Game/Logic/Behaviors/Shoot.cs#L29-L55)); reference `Cooldown.Normalize()` substitutes 1000 ([Cooldown.cs](https://github.com/ossimc82/fabiano-swagger-of-doom/blob/6fd20aad4a7905b13f25389c68368a942a2b68cb/wServer/logic/Cooldown.cs#L20-L25)). Therefore omitted cooldown is not itself a faster-fire cause. With the checked default tick rates, a repeated normalized 1000ms attack fires every 1000ms in target and 1050ms in reference. With cooldown variance, the target snaps sampled jitter to its tick interval ([MathUtils.NextIntSnap](https://github.com/kevinbudz/realm-server/blob/bb75bc1e438b465986a8ada354b6332f69e0e3a6/Utils/MathUtils.cs#L56-L67)); reference adds an integer-ms random variance ([Cooldown.Next](https://github.com/ossimc82/fabiano-swagger-of-doom/blob/6fd20aad4a7905b13f25389c68368a942a2b68cb/wServer/logic/Cooldown.cs#L34-L38)) and the tick loop quantizes when it can fire. A variance large enough to leave a nonpositive cooldown reaches the next-tick minimum and can change direction because target ticks are 100ms while reference default ticks are 50ms; do not extrapolate the normal positive-cooldown result to such cases.

On state entry, each side initializes from `cooldownOffset` (target `Enter`, same target Shoot lines 57–62; reference `OnStateEntry`, reference Shoot lines 45–48). A zero offset allows the first shot on the first behavior tick in both; positive offsets inherit the same decrement-before-check versus check-before-decrement distinction.

## Aim, spread, status effects, and invalid indices

**Predictive aiming is semantically different even with identical enemy parameters.** `Beholder` has `predictive: 0.5` on its same five-shot attack in both definitions (links above). Target uses that number as a probability: on each volley, it randomly either leads the target by four times its one-tick movement delta or aims directly at the current position ([target Shoot](https://github.com/kevinbudz/realm-server/blob/bb75bc1e438b465986a8ada354b6332f69e0e3a6/Game/Logic/Behaviors/Shoot.cs#L95-L104), constant at [line 14](https://github.com/kevinbudz/realm-server/blob/bb75bc1e438b465986a8ada354b6332f69e0e3a6/Game/Logic/Behaviors/Shoot.cs#L14)). Reference always estimates angular velocity from a 100ms history sample and multiplies the correction by projectile speed/100 and by the `predictive` scalar ([reference Shoot](https://github.com/ossimc82/fabiano-swagger-of-doom/blob/6fd20aad4a7905b13f25389c68368a942a2b68cb/wServer/logic/behaviors/Shoot.cs#L50-L63), applied at [lines 80–84](https://github.com/ossimc82/fabiano-swagger-of-doom/blob/6fd20aad4a7905b13f25389c68368a942a2b68cb/wServer/logic/behaviors/Shoot.cs#L80-L84)). A player sees intermittent full four-tick lead versus no lead in target; the reference produces a continuous speed-scaled correction. This changes where volleys land, not their cadence. It is a confirmed implementation divergence; whether target’s probability interpretation is an intentional redesign is unverified.

**Dazed changes projectile count only in target `Shoot`.** Target halves the configured count with ceiling while Dazed ([target Shoot lines 72–75](https://github.com/kevinbudz/realm-server/blob/bb75bc1e438b465986a8ada354b6332f69e0e3a6/Game/Logic/Behaviors/Shoot.cs#L72-L75)); reference keeps the configured count ([reference Shoot lines 71–95](https://github.com/ossimc82/fabiano-swagger-of-doom/blob/6fd20aad4a7905b13f25389c68368a942a2b68cb/wServer/logic/behaviors/Shoot.cs#L71-L95)). In the shared Brown Den Spider example, Dazed reduces the three-shot spread to two bullets in target and leaves three in reference. That is a deliberate-looking status mechanic in the target, not evidence of excess firing. Both implementations suppress an attack while Stunned, and both continue to let the cooldown count down; a due shot resumes once Stun is gone.

For normal non-Dazed volleys, both compute a centered spread from `count` and `shootAngle`; a one-shot attack ignores the spread angle. Both convert configured angles from degrees to radians. `fixedAngle` overrides target aim; otherwise `defaultAngle` is used when no player is found. Target additionally supports per-volley `rotateAngle`, which the reference `Shoot` constructor does not expose. These differences can alter headings/patterns, not base repeat cadence. The target explicitly avoids shooting if the requested projectile dictionary key is missing and consumes cooldown ([target Shoot lines 79–85](https://github.com/kevinbudz/realm-server/blob/bb75bc1e438b465986a8ada354b6332f69e0e3a6/Game/Logic/Behaviors/Shoot.cs#L79-L85)); reference indexes its projectile array directly ([reference lines 75–80](https://github.com/ossimc82/fabiano-swagger-of-doom/blob/6fd20aad4a7905b13f25389c68368a942a2b68cb/wServer/logic/behaviors/Shoot.cs#L75-L80)), with behavior exceptions caught/logged by its `Behavior.Tick`. That only changes malformed/mismatched projectile configurations.

## Grenade and telegraph behavior

`Grenade` has the same decrement/check ordering as `Shoot`, so its positive cooldown can also resolve one tick sooner in target. Its zero-cooldown default is also 1000ms on both sides. The implementation surfaces differ: target allows configurable travel time (default 1500ms), condition effect/duration, and color, and places fixed-angle targets relative to the enemy’s current position ([target Grenade constructor and setup](https://github.com/kevinbudz/realm-server/blob/bb75bc1e438b465986a8ada354b6332f69e0e3a6/Game/Logic/Behaviors/Grenade.cs#L25-L51), [target throw/timer](https://github.com/kevinbudz/realm-server/blob/bb75bc1e438b465986a8ada354b6332f69e0e3a6/Game/Logic/Behaviors/Grenade.cs#L58-L113)). Reference hardcodes a 1500ms timer and no debuff payload; its fixed-angle position is `(range*cos, range*sin)` without adding the host position ([reference Grenade](https://github.com/ossimc82/fabiano-swagger-of-doom/blob/6fd20aad4a7905b13f25389c68368a942a2b68cb/wServer/logic/behaviors/Grenade.cs#L23-L31), [targeting and resolution](https://github.com/ossimc82/fabiano-swagger-of-doom/blob/6fd20aad4a7905b13f25389c68368a942a2b68cb/wServer/logic/behaviors/Grenade.cs#L38-L86)). Treat that origin-relative fixed-angle path as a legacy implementation quirk/porting hazard: the old behavior file has no active fixed-angle enemy initializer found in this pass, so this is not a demonstrated shared-enemy regression. Target’s grenade argument order is `(range, damage, radius, ...)`, while reference is `(radius, damage, range, ...)`; target database calls use named `radius`/`range` arguments. Positional calls should not be carried across APIs without rechecking meaning.

`Flash` is only a state-entry visual telegraph in both trees; it does not delay or schedule a later attack itself. Target broadcasts a flash effect on `Enter` ([target Flash](https://github.com/kevinbudz/realm-server/blob/bb75bc1e438b465986a8ada354b6332f69e0e3a6/Game/Logic/Behaviors/Flash.cs#L12-L24)); reference broadcasts its flashing packet on state entry ([reference Flash](https://github.com/ossimc82/fabiano-swagger-of-doom/blob/6fd20aad4a7905b13f25389c68368a942a2b68cb/wServer/logic/behaviors/Flash.cs#L18-L38)). Any warning-to-explosion gap comes from the surrounding state transition/timer and attack behavior, not from `Flash`. Neither tree has a standalone behavior class named `Explode` in the reviewed behavior directories; explosions are expressed by combinations such as timed `Shoot`/`Grenade`/`Suicide`/`Decay`.

## Coverage and limits

Reviewed primitive implementations: `Shoot`, its reference `Cooldown` helper and each tree’s tick interval setup; target `Grenade` versus reference `Grenade`; and `Flash`. Cross-checked same-parameter enemy definitions for Brown Den Spider and Beholder. Also confirmed the reference’s custom `SnakePitTowerShoot` is a specialized `Shoot` subclass that chooses a fixed firing direction from nearby map geometry ([reference class](https://github.com/ossimc82/fabiano-swagger-of-doom/blob/6fd20aad4a7905b13f25389c68368a942a2b68cb/wServer/logic/behaviors/SnakePitTowerShoot.cs#L12-L46)); target has no equivalent primitive class, and its Snakepit Dart Thrower initializer omits a shooting action (definition-level finding documented separately). This note does not compare Follow/Wander movement, projectile travel/physics/collision, all specialized attack classes, or every enemy’s parameter tuning. It does not label the 2015 reference as proof of 2014 intent.
