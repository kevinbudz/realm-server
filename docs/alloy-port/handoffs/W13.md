# W13 — Leveled async file logging

Status: done (2026-10-15). Developed in an isolated copy and applied as a patch. Not committed.

## What changed
- `Common/LogFiles.cs` (new): per-level file sinks, a dedicated `LogWriter` thread, rotation, drops and retention.
  The file header documents the design.
- `Program.cs`: `Print` still writes the same console line, and also enqueues it for the file sink. `LogFiles.Start()` runs
  before `Settings.Init` and is skipped for `*-verify` runs. `LogFiles.Shutdown()` runs last in `Terminate`.

## Behavior
- **Files:** `logs/{info,warn,error,debug}/YYYY-MM-DD.log` under the process cwd, so `bin/<cfg>/net8.0/logs/` with the
  `debug`/`release` scripts. Each line goes to exactly one file; warn and error are not copied into info. `debug/` only exists
  in Debug builds. Lines carry a local timestamp with ms and the level.
- **Rotation:** at the date change, and by size (64 MiB → `DATE.N.log`). A restart appends to the existing file.
- **Queue:** bounded (65,536 records and 4M chars). When it overflows, records are dropped and the count is reported in one
  warn line. The main thread never blocks.
- **Flushing:** every ~1 s and on clean shutdown. A `kill -9` loses about 0.4 s of lines.
- **Failure:** the first I/O error disables every file sink, with one console warning. The server keeps running.
- **Retention:** `REALM_LOG_RETENTION_DAYS` (default 30; 0 = keep everything). The writer thread prunes at startup and at each
  date change. It deletes only regular files named exactly `YYYY-MM-DD[.N].log`, directly inside the four level dirs and dated
  before the cutoff. It never follows symlinks, never recurses, and never deletes the active file.
- **Environment variables:** `REALM_LOG_FILES=0`, `REALM_LOG_DIR`, `REALM_LOG_MAX_BYTES`, `REALM_LOG_QUEUE_MAX`,
  `REALM_LOG_RETENTION_DAYS`, `REALM_LOG_CLOCK_OFFSET_S` (test hook only).

## Open
- Startup writes about 20k debug lines (~2 MB) in Debug builds. Retention bounds the total.
- Two processes sharing one cwd would interleave lines in the same files. Not tested, and not supported.
