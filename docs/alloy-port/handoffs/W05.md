## Changed in this pass
- **`Game/W05Verify.cs`, `CheckDungeonGenBudget`: the `CreateDungeonWorld` part.** This check was flaky, not a product bug. It set
  `Generator.MaxWork = 50` and expected all three build attempts to exceed it. `Manager.CreateDungeonWorld` draws a random `Guid`
  seed, though, and about 5% of Mad Lab seeds fit in 50 work units (measured: 50 of seeds 1..1000 finish in ≤ 50; the work range
  is 20 to 363). Measured directly, 31 of 200 `CreateDungeonWorld` calls built a world at budget 50. So the check failed in roughly
  one run in seven. The first full run here failed on it (`4 -> 5`), which matches the handoff's old open item. The product path was
  already right: `DungeonWorld.BuildMap` retries three seeds and rethrows before `AddWorld` runs. The fix sets the budget to 0 for
  that part only. Every generation spends a unit on its first step, so every seed fails. The same measurement at budget 0 gave
  200 of 200 throws. The seed-1 check (budget 50, fixed seed) is unchanged.
- The measurement used a throwaway copy of HEAD outside the repo, with a diagnostic flag. Nothing from it is in the repo.
- Measurement-only toggles `REALM_TOGGLE_NOSTATICS` and `REALM_TOGGLE_NOJOIN` were removed earlier and are not used.

## Open
1. **Hop median and max are above the W04 record.** W04's notes (`.claude/agent-memory-local/fusion-sidekick/hop-latency-finding.md`)
   give 9.52 / 12.89 ms for the same Debug trace-on config. Three runs here give 11.3–11.4 / 20.4–23.2 ms, and the Release
   no-trace run gives 9.2 / 14.4 ms. I could not reproduce W04's number or explain the gap. An A/B against a W04 build on this VM
   is not possible, since W00–W13 are one commit (`0173759`) with no W04-only build. The W05 code on the hop path is small: a length
   check in `Hello` (`GameServer.Handlers.cs`), `PendingJoin == null` guards in Create and Load, and `StaticGrid` is called only for
   static add, remove and move (`World.cs:577, 608, 688`), never for a player join. So I don't think W05 caused it, but it is not
   proven. If the hop gate must be settled before commit, rerun W04 on this VM and compare.
2. The Release CS0169 warning (`Networking/Client.cs:145`) predates W05 and was left alone (see the gates table).
3. `--projpath-verify <golden>` is not run (no realm-cpp golden file here).
4. The soak saw one tick period of 133 ms (Debug) and 165 ms (Release) under load. That is well under the 1 s stall limit, but I
   did not look at its cause.
5. The `static index order keys …: Id order matches enumeration: False` lines are `Info` output, not checks. The index order is the
   `Statics` enumeration order, which is what the passing check tests.
