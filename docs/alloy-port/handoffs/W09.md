# W09 — Closed-form projectile paths for hit validation

Status: done (2026-10-14). Developed in an isolated copy and applied as a patch. Not committed.

## What changed
- `Game/ProjectilePath.cs` (new): `Evaluate(desc, startX, startY, angle, bulletId, elapsedMs, out x, out y)` and `PositionAt(...)`.
  It is a literal port, in double, of realm-cpp `src/objects/ProjectileProperties.cpp:6-55`.
- `Game/Projectile.cs`: `PositionAt` now takes a double and calls `ProjectilePath`. That carries the same fixes into
  `VerifyProjectiles` / `SweepAckedInterval` and `TryHitSquare`.
- `Game/Entities/Player.Projectiles.cs`: `TryHitEnemy` keeps its validation and logging, then calls `ResolveEnemyHit`. That runs a
  cover sweep (`CoverClearAlongPath`, steps of at most 16 ms and 0.5 tile, bisecting longer steps; the hit point is included),
  then one exact position evaluation. The acceptance constants are unchanged. A hit with a wall on its path is dropped
  (no disconnect), as before.
- `Game/ProjectilePathVerify.cs` (new), plus `Program.cs --projpath-verify [golden.bin]`.
- `Game/Entities/Player.ProjectileReplay.cs` (new, test-only): the replay driver plus a copy of the old resim. It can be deleted once
  nobody needs the before/after comparison.
- `tools/projpath/extract_descs.py`, `golden_harness.cpp` (new): regenerate the C++ golden file (~60 MB, not checked in).

## Parity bugs found and fixed (server vs client)
- The client parses `Speed` with `integer()` (`realm-cpp Catalog.cpp:330`), so a Speed of 0.02 becomes 0 on the client. The truncation
  is applied in the path math only; `ProjectileDesc.Speed` is unchanged.
- The client's `id % 2 ? 1 : -1` is true for negative odd ids. The server's `== 1` flipped the parametric x sign.

## Not met / decisions
- **The 10-minute bot soak was not run.** `Bot.TryBotShoot` (`Bot.cs:286-337`) calls `HitByProjectile` directly, and `hop_client.py` cannot
  shoot. The replay stands in for it. The smallest real soak would extend `hop_client.py` with PlayerShoot + EnemyHit against an enemy
  in range.
- Lead decision: keep the 16 ms / 0.5-tile sweep. It is at least as dense as a 60 fps client, which tests the projectile's tile per frame.
  A client running below ~30 fps could clip a corner that the server then refuses. The cost is one dropped hit, and this closes the
  wall-hit hole. Revisit if players report it.
