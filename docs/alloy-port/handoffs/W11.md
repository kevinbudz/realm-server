# W11 — Attribute-based commands with rank levels

Status: done (2026-10-15). Developed in an isolated copy and applied as a patch. Not committed.

## What changed
- `Common/Rank.cs` (new): Player 0, Donor 10-40, Mod 80, Dev 90, Admin 100.
- `Game/Commands/CommandAttribute.cs`, `CommandCall.cs`, `CommandTable.cs` (new): `[Command("name", Rank.X, aliases…)]` on `Player`
  methods, discovered by reflection. `RunCommand` checks the caller's rank for **every** command (Alloy only checked Admin).
- `Game/Commands/Player.Commands.Basic.cs` and `Player.Commands.Admin.cs` (new): 80 handlers. A script copied the bodies mechanically
  from the old switch and removed only the gate and the terminal `break`.
- `Game/Entities/Player.Chat.cs`: the switch is now a single `RunCommand` call.
- `Common/Models.cs` (AccountModel): `Rank` field. `Ranked` is now derived (`Rank >= Admin`, with a setter). Loading an account with
  `Ranked=true` and a lower Rank maps it to Admin. Export writes both fields. All `Ranked` readers behave the same, including
  the editor check at `GameServer.Handlers.cs:602` and `/mute`.
- `/commands` is built from the registry and filtered by rank, in the same format. Admins see 106 names, and the old hand-written list of 82 is fully contained.
  Rank 0 sees 49 names.
- `tools/hop/chat_check.py` (new). `hop_client.py`'s `Conn` takes `source=`.
