# W03 — Remove synchronous main-thread DB writes

Status: done (2026-10-15). Not committed. The tick-time gate is open: the remaining spike isn't DB-related, and its fix moved to W05.

## Design
- **Busy handler (from W01):** `OpenConnection` installs the native `sqlite3_busy_handler` (1 ms steps through a rooted static
  delegate; throws if rc != 0) **after** the PRAGMA batch. `busy_timeout` is dropped, and `Default Timeout=5` is in the connection string.
- **Read-your-writes overlay** (`Database.cs` `_pending`, `QueuePlain`, `ReleasePending`, `GetKey` ~:1088): each queued bundle's
  keys are visible to `GetKey` until its commit attempt ends. Every production read goes through `GetKey`, including GetKeyLines,
  Reload, the char list, vault, guild, login and legends. There are no prefix scans. Entries are released on commit, rollback,
  failed batch, writer death, queue-race fallback and shutdown. In the soak, pending peaked at 3 and ended at 0.
  This also closes the stale-read race W02 found (Hello `GetKey` vs a still-queued disconnect save).
- **Purchases, renames, guild changes:** the check and the debit happen on the main thread against the overlay. The debit is queued,
  and the reply comes from the commit outcome (`WriteAtomicallyThen` / `DbJob.Outcome(bool)`). A failed commit refunds and reports
  failure. Two purchases in a row see the first debit, and the writer's FIFO order backs that up.
- `Transact`, `WriteAtomicallyAndWait` and `FuncJob.Done` are removed. The WAL PASSIVE checkpoint moved from `Database.Tick` to the writer thread.
