# W02 — Hello account save through the writer queue

Status: done (2026-10-14). Not committed.

## Audit
- No code gates a login on the **DB** value of `Account.Connected`. `Database.IsAccountInUse` (`Common/Database.cs:1133-1155`)
  reads it only to clear it in memory. Every "Account in use!" path checks the in-memory `Manager.GetClient` / `HasHandoff`
  instead: `GameServer.Handlers.cs:598`, `AppServer.Handlers.cs:49,80,156,180,205,230`, `AppServer.Social.cs:31,74`.
  The live gate is `Manager.LinkClient` (`GameServer.Handlers.cs:642`), which runs on the same tick as the enqueue.
  An uncommitted `Connected=true` therefore opens no duplicate-login window.
- The writer is FIFO, so the old session's `Connected=false` save is queued ahead of this one and the final DB value is `true`.
- No later reader in the same tick needs the row committed. Load reads the character rows. CreateCharacter and DeleteCharacter
  use the in-memory account and enqueue after this save, in FIFO order.
- **Deferred to W03 (pre-existing, not widened by W02):** a non-handoff Hello `GetKey` (`GameServer.Handlers.cs:563`) can read a
  snapshot older than a still-queued async disconnect save (`Client.cs:302`).

## What changed
- `Common/Models.cs:468`: new `AccountModel.SaveAsync()`. It exports on the tick thread, then queues the write with
  `Database.WriteAtomically(AccountKey(Id))`.
- `Networking/GameServer.Handlers.cs:639-640`: `Save()` → `SaveAsync()`. The `[hop]` mark is renamed "after acc save enqueued".
- `tools/hop/analyze.py`: recognizes the new label and keeps the old one for older logs.
- `tools/hop/dup_login.py` (new): duplicate-login and persistence checks, 16 in total.
